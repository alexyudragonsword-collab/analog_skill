Analog Studio User Manual

Analog Studio is an analog IC design and simulation workbench built on the ngspice simulator and PTM (Predictive Technology Model) process models. It provides four tools: the gm/ID Designer, ngspice teaching examples, a characteristic-curve browser, and comparison plots.

1. Prerequisite: installing ngspice

The application relies on a system-installed ngspice simulator:

  • Windows: download the zip from ngspice.sourceforge.io and extract the Spice64/ folder next to the application exe (zero configuration); or extract anywhere and set the path to ngspice.exe in Settings
  • Linux: sudo apt install ngspice
  • macOS: brew install ngspice

After launching, check the status bar at the bottom right:

  • ngspice ✓ green — detected, ready to go
  • ngspice ✗ red — not found; a red banner appears at the top and run buttons are disabled. Click the indicator or the Locate… button to open Settings and point to the executable

2. gm/ID Designer (first tab)

A transistor sizing tool based on the gm/ID methodology: the transconductance efficiency gm/ID is the pivot variable, and sizing is done with simulation-generated lookup tables instead of long-channel equations — accurate even in advanced nodes.

2.1 Building a lookup table

  1. In Lookup table, pick a process model (nmos180 / pmos180 / nmos45hp / pmos45hp / nmos22hp / pmos22hp; VDD is shown in the dropdown)
  2. Set the reference width W (results are W-independent; the default 10 um is fine), channel length L, and Vds (check auto for VDD/2)
  3. Click Build / Load Table. The first build runs ngspice sweeps (seconds to tens of seconds; progress streams into the log panel). Results are cached — subsequent builds with the same parameters load instantly (the log shows [cache])

Once built, the label below the button shows the table's valid range: gm/ID span, maximum fT, and gm·ro at gm/ID = 15. The right side displays four design charts — fT, Id/W (log scale), gm·ro, and Vgs & Vov — all versus gm/ID.

Available models: beyond the three built-in nodes (180 / 45hp / 22hp), the app registers the full PTM bulk-CMOS library — 130 / 90 / 65 nm, 45 nm LP, 32 nm HP/LP, 22 nm LP — for 20 nmos/pmos models, plus the PTM-MG FinFET nodes (7 / 10 / 14 / 16 / 20 nm, in HP and LSTP flavours, 20 nmos/pmos models tagged [FinFET] in the dropdown).

2.1a FinFET (BSIM-CMG, 7–20 nm)

FinFET devices use the BSIM-CMG model (SPICE level 72). Most prebuilt ngspice binaries do not compile BSIM-CMG in, but ngspice ≥ 38 supports runtime model loading via OSDI: the app ships a precompiled bsimcmg.osdi and loads it with pre_osdi before each simulation, so FinFET runs on a stock OSDI-capable ngspice.

  • The size variable is NFIN (fin count), not W: selecting a FinFET model turns the "W" field into an integer NFIN and locks L to the node's fixed gate length (e.g. 11 nm at 7 nm, 24 nm at 20 nm). Effective width Weff = NFIN×(2·HFIN+TFIN); sizing reports the required NFIN and Weff, with current density as Id/Weff.
  • Real device capacitances: gate caps are read from the BSIM-CMG operating point (cgg/cgs/cgd), not the planar Cox·W·L approximation (invalid for a tri-gate fin). The Browser's "Gate capacitances" plot shows the real swept caps for FinFET.
  • Requirement: your ngspice must support OSDI (official builds generally do). If it does not, or no .osdi ships for your platform, the FinFET entries are greyed out. Designer / Browser / Comparison usage is otherwise identical to bulk.

FinFET designer: the size knob is NFIN, L is locked to the node, and the result reports NFIN / Weff.

2.2 Computing an operating point (sizing)

Pick one of three modes in the Sizing box:

  • Size by gm/ID: specify gm/ID, then fix exactly one of Id, W, or gm; the rest is solved. Example: gm/ID = 15, Id = 100 uA → W ≈ 10 um
  • Size for fT ≥ target: given a minimum fT, automatically selects the highest gm/ID that still meets it — i.e. the lowest-power operating point. Suited to bandwidth-constrained designs
  • Size for gm·ro ≥ target: given a minimum intrinsic gain, again picks the most power-efficient point. Suited to high-gain stages

Click Compute Operating Point. The result appears in engineering units in the table at the bottom left (W, Id, gm, Vgs, Vov, fT, gm·ro, Id/W), and the operating point is marked on all four charts with a red dashed line and dot. Copy as text puts the result on the clipboard.

If a target exceeds what the table can deliver (e.g. fT above the maximum), the error is shown inline in red — nothing crashes.

2.3 Tools: quick lookup and self-check

  • Quick lookup: enter any gm/ID value, pick a quantity (Id/W, fT, Vgs, Vov, gm·ro, gm, Id) and click Look up for the interpolated scalar — no full sizing needed
  • Run self-check: runs 5 physical-consistency tests on the current table (weak-inversion limit, Id/W monotonicity, channel-length scaling, fT×gm/ID peak, Vds sensitivity), shown as a PASS/FAIL list with the numbers in the log panel. Use it to confirm the model/simulation data is physically sane

3. ngspice Examples (second tab)

Nine standard SPICE teaching examples covering DC, AC, transient and noise analyses:

  1. Tran — RC charging (voltage and current)
  2. DC — NMOS Id-Vds family of curves
  3. AC/Noise — RC low-pass frequency response and output noise
  4. Tran — sample-and-hold switch comparison (real NMOS vs ideal switch)
  5. Tran — kT/C noise time-domain statistics (histogram + Gaussian fit)
  6. DC — NMOS current mirror output characteristics
  7. AC — common-source amplifier Bode plot
  8. DC — transmission-gate on-resistance (180/45/22nm comparison)

Usage: select an example in the left list → adjust parameters in the form (resistances, capacitances, device sizes, bias voltages; Reset defaults restores them) → click Run simulation. The run executes in the background with live progress in the log panel; the resulting plot appears on the right when done.

The plot viewer supports wheel zoom and drag panning; Fit refits the view, Save as… exports the PNG and Open folder reveals the output directory.

Advanced parameters: each example shows its common parameters directly; expanding the collapsible Advanced parameters group exposes formerly hard-coded values — supply voltage VDD, sweep ranges and steps, frequency ranges, timing/clock, temperature, the sample-capacitor set, and more. (Note: the number of configurations per example — e.g. RC's two configs, the transmission gate's three nodes — is fixed by structure; the gate's Vpass sweep step lives inside a source function and is not tunable in this version.)

4. Curve Browser (third tab)

Generates standard characterization plots for any process model — useful for node comparison and device evaluation before design:

  • gm/ID four-quadrant: gm/ID vs Vov (with the BJT limit and the 2/Vov asymptote), Id/W vs gm/ID, fT vs gm/ID, and gm·ro vs gm/ID, with multiple Vds curves overlaid
  • IV characteristics: Id-Vov in linear/log scale, full Id-Vgs sweep, and the Id-Vds output family
  • Gate capacitances: Cgg/Cgs/Cgd/Cgb vs Vgs (analytical model, fast)

Choose model, plot type, W and L, then click Generate / Show. Plots are cached per parameter set within the session; Regenerate forces a fresh simulation.

5. Comparison plots (fourth tab)

Overlays several gm/ID curves on one four-quadrant figure for direct comparison. Three modes:

  • Channel-length comparison: pick one model and enter several lengths in L list (comma-separated, e.g. 0.18, 0.36, 1.0) to show the fT-down / gm·ro-up trade-off as L grows
  • Cross-node comparison: multi-select several same-polarity models (e.g. nmos180 / nmos45hp / nmos22hp) to compare the speed–gain characteristics across technology generations
  • Gate-capacitance comparison: multi-select models for a side-by-side gate-capacitance comparison

Results are session-cached and support zoom/save. Cross-node and capacitance comparisons require all selected models to share one polarity (all nmos or all pmos), otherwise an inline red error is shown.

6. Log panel and job queue

The Simulation log panel at the bottom streams all simulation progress and ngspice output in real time; on failure it includes the error details plus the tail of the latest ngspice log file. The panel can be docked to the right or floated.

All simulation jobs go through a single background queue and run serially: launching several jobs queues them in order, the UI stays responsive throughout, and the currently running job is shown at the left of the status bar.

7. Troubleshooting

SymptomRemedy
Red banner "ngspice not found" Install ngspice (section 1), or click Locate… and set the path manually
Table build is slow The first build runs full sweeps — that is normal. Identical parameters hit the cache from the second time on (instant)
Sizing shows a red error The target exceeds what this model/length can deliver; increase L (raises gm·ro) or relax the target
A simulation fails Check the error details in the log panel; common causes are missing model files or parameters far outside a reasonable range


Output locations: in development mode, plots/ and logs/ inside each toolkit directory; in the packaged build, under AnalogStudio/workspace/ in the per-user data directory — the installation directory is never written to.
